# Архитектура и решения

## С чем боремся (ТСПУ, 2025–2026)

| Метод блокировки | Кого бьёт | Наш ответ |
|---|---|---|
| Сигнатуры протоколов | WireGuard, OpenVPN, IPsec, L2TP | Не используем. Трафик выглядит как обычный TLS 1.3 |
| Эвристика «полностью случайного» трафика | Shadowsocks, VMess, obfs4 | Reality: настоящее TLS-рукопожатие с отпечатком Chrome |
| Активное зондирование сервера | Trojan и VLESS-TLS со своим доменом | Без ключа Reality проксирует на настоящий сайт (`--sni`), и сервер ничем не выдаёт себя |
| Обрыв после ~16–20 КБ к IP популярных хостингов | Все протоколы | Выбор хостинга ([HOSTING.md](HOSTING.md)), позже каскад |
| Замедление UDP/QUIC | Hysteria2, TUIC, WireGuard | Работаем только по TCP/443 |
| Порты кроме 443 | Всё, что на нестандартных портах | Всё на одном порту 443, XHTTP идёт через fallback |
| Белые списки в мобильных сетях | Все зарубежные IP | Этап 4: каскад через сервер в РФ |

## Решения

* **Xray-core, VLESS + Reality.** Самое проверенное на сегодня средство против ТСПУ;
  его развивают те же люди, которые годами работают против GFW.
* **Два транспорта на одном порту.** Vision (raw) даёт скорость, XHTTP подстраховывает, если
  длинные соединения начнут резать. XHTTP принимается через `fallbacks` Vision-входа на
  абстрактный unix-сокет, поэтому снаружи открыт только 443.
* **Свой клиент не пишем.** Ссылки `vless://` и подписки понимают все популярные
  клиенты, поэтому все платформы поддерживаются бесплатно.
* **Состояние в одном YAML-файле, всё остальное генерируется.** Утилита отвечает за
  логику (ключи, пользователи, конфиги) и покрыта тестами. Ansible отвечает за
  доставку на сервер: делает это идемпотентно и по одной ноде за раз (`serial: 1`).
  Когда понадобится коммерция, YAML заменим на БД, не трогая генераторы.
* **Надёжность деплоя:**
  * версия Xray закреплена, скачанный архив сверяется по sha256;
  * новый конфиг проверяется новым бинарником до переключения;
  * каждая версия лежит в своей папке `/opt/xray/<version>`, а `current` —
    ссылка на активную, поэтому откат делается одной правкой версии;
  * systemd перезапускает Xray при падении. Xray работает от непривилегированного
    пользователя только с правом `CAP_NET_BIND_SERVICE`, файловая система
    для него только на чтение;
  * фаервол открывает SSH до включения. Пароли SSH отключаются только если есть ключ.
* **Приватность:** access-логи выключены. Трафик считается по пользователям (Xray Stats
  API на `127.0.0.1:10085`), но без адресов сайтов.
* **Защита сервера от злоупотреблений:** заблокированы торренты и обращения к приватным сетям.

## Проверки

* `make test`: юнит-тесты генераторов и CLI. Если `xray` есть в PATH, конфиг
  проверяет сам Xray.
* `make integration`: деплой с нуля в контейнер Ubuntu 24.04 с systemd, затем
  повторный деплой (должен ничего не менять), подключение настоящим клиентом по
  обоим транспортам, проверка, что зондирование видит чужой сайт, и что
  отключённый пользователь теряет доступ.

## Дорожная карта

**Этап 1 (готово):** выходные ноды VLESS Reality (Vision + XHTTP на 443), CLI,
Ansible, тесты.

**Этап 2: надёжность для себя**
* Подписка по HTTPS-ссылке: клиенты сами подтягивают новые серверы, SNI и ключи, и
  не нужно заново раздавать ссылки.
* Мониторинг «изнутри»: проба из РФ (домашний ПК или дешёвый российский VPS) раз в N
  минут пытается пройти через каждую ноду и присылает уведомление в Telegram при сбое.
* Автоматический бэкап `state/bibvpn.yml` в зашифрованном виде (age/sops).

**Этап 3: больше запасных вариантов**
* Несколько нод у разных провайдеров, `urltest` и балансировка в подписке.
* AmneziaWG как альтернатива на UDP (для сетей, где UDP не режут; даёт полноценный VPN
  для роутеров).
* XHTTP через CDN: IP сервера скрыт за CDN, для заблокированного по IP сервера.

**Этап 4: белые списки**
* Роль `relay`: нода в РФ (в подсети, которая есть в белых списках) принимает
  клиентов и пересылает трафик на выходную ноду за границей. Поле `role` в модели
  данных уже есть.

**Этап 5: коммерция**
* БД вместо YAML, API и веб-панель, Telegram-бот.
* Лимиты трафика и сроки подписки: добавлять и удалять пользователей через Xray
  HandlerService API без перезапуска. API уже включён.
* Оплата, учёт.
* Юридическая часть: в РФ действуют ограничения на предоставление и рекламу
  средств обхода блокировок. Перед запуском нужна консультация юриста.
