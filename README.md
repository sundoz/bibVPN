# bibVPN

[![CI](https://github.com/sundoz/bibVPN/actions/workflows/ci.yml/badge.svg)](https://github.com/sundoz/bibVPN/actions/workflows/ci.yml)

Свой обход блокировок в России: серверы на **Xray (VLESS + Reality)** за границей,
**хаб** в России для подписок и мониторинга, и одна утилита командной строки, которая
всем этим управляет. Клиенты берём готовые (Happ, v2rayNG, v2rayN, Hiddify, v2RayTun,
Streisand…), поэтому поддерживаются Android, iOS, Windows, macOS и Linux.

> Впервые видите слова «Reality», «SNI» или «подписка»? Начните с
> [подробного руководства](docs/GUIDE.md): там всё объяснено с нуля.

## Возможности

- **Маскировка под обычный сайт.** Подключение для ТСПУ выглядит как заход на настоящий
  зарубежный сайт по HTTPS (TLS 1.3, отпечаток Chrome). Зондирование сервера без
  ключа видит настоящий сайт с настоящим сертификатом. Домен и сертификат не нужны.
- **Три способа подключения на порту 443.** По TCP: Vision (быстрый, основной) и
  XHTTP (устойчивее к поведенческому анализу и замедлению длинных соединений). По
  UDP: Hysteria2 (QUIC, для ТСПУ выглядит как HTTP/3), запасной путь на случай, когда
  режут TCP.
- **Подписки.** Каждый пользователь получает одну личную ссылку. Смена IP, SNI, ключей
  или новые серверы доходят до приложений сами. Рабочие серверы идут первыми,
  сломанные помечаются ⚠.
- **Мониторинг из России.** Хаб каждые 5 минут проверяет каждый сервер настоящим
  туннелем, включая скачивание ~1 МБ (ловит «заморозку после 16–20 КБ»), различает
  три вида блокировок и пишет в Telegram, когда что-то сломалось и когда починилось.
- **Развёртывание одной командой.** Ansible настраивает и защищает серверы: фаервол,
  вход только по ключу (с проверкой итоговой конфигурации sshd), fail2ban,
  автообновления, BBR, песочница systemd для Xray. Повторный запуск ничего не меняет.
- **Безопасные обновления.** Версия Xray закреплена и сверяется по sha256. Новый конфиг
  проверяется новым бинарником до переключения. Серверы обновляются по одному.
- **Приватность.** Журналы посещений и запросов выключены везде.
- **Проверено.** 168 юнит-тестов и интеграционный тест, который разворачивает сервер и
  хаб в контейнерах и проверяет подключение, безопасность, подписки, уведомления и
  отзыв доступа. Всё это гоняется в CI.

## Как это устроено

```
  ┌────────────────────┐   bibvpn deploy (Ansible по SSH)
  │ ваш компьютер      │ ─────────────────────────┬───────────────────────────┐
  │ state/bibvpn.yml   │                          ▼                           ▼
  │ (все ключи)        │            ┌──────────────────────────┐   ┌─────────────────────┐
  └────────────────────┘            │ ХАБ, VPS в России        │   │ СЕРВЕРЫ за границей │
                                    │ • подписки (Caddy, HTTPS)│   │ • Xray :443         │
  ┌────────────────────┐  подписка  │ • мониторинг каждые 5 мин├──▶│   Reality: Vision + │
  │ телефон / ноутбук  │◀───────────┤ • уведомления в Telegram │   │   XHTTP, Hysteria2  │
  │ готовый клиент     │            └──────────────────────────┘   └──────────▲──────────┘
  │                    │ ── туннель, для ТСПУ похож на HTTPS к www.<сайт> ───┘
  └────────────────────┘
```

Всё состояние (серверы, ключи Reality, пользователи, токены подписок) хранится в одном
файле `state/bibvpn.yml`. Конфиги серверов, инвентарь Ansible, ссылки и подписки
генерируются из него, поэтому ручные правки на серверах откатываются следующим
`deploy`.

## Быстрый старт

Нужно: компьютер с Linux/macOS (на Windows используйте WSL), Python 3.10+, git;
VPS за границей на Ubuntu 22.04+/Debian 12+ (как выбрать: [HOSTING.md](docs/HOSTING.md));
по желанию второй VPS в России для хаба.

```bash
# 1. Установка
git clone https://github.com/sundoz/bibVPN.git && cd bibVPN
make dev && source .venv/bin/activate

# 2. Доступ к серверам по ключу (при деплое пароли SSH отключаются)
ssh-copy-id root@<IP сервера>
ssh-copy-id root@<IP хаба>

# 3. Серверы и пользователи
bibvpn init
bibvpn check-target www.some-site.fi              # подходит ли сайт для маскировки
bibvpn node add fi1 <IP сервера> --sni www.some-site.fi
bibvpn user add me

# 4. Хаб (рекомендуется)
bibvpn hub set <IP хаба>                          # домен по умолчанию: <ip>.sslip.io
bibvpn monitor set --telegram-token <от @BotFather> --telegram-chat-id <ваш id>

# 5. Развёртывание и проверка
bibvpn deploy --check                             # предпросмотр без изменений
bibvpn deploy
bibvpn monitor test                               # тестовое сообщение в Telegram
bibvpn status                                     # результаты проверок с хаба

# 6. Подключение
bibvpn sub me --qr                                # подписка: вставить или отсканировать в приложении
bibvpn links me --qr                              # или отдельные ссылки, если хаба нет
```

**Сделайте резервную копию `state/bibvpn.yml`.** Это единственное место, где хранятся
ключи. Файл в `.gitignore` и в репозиторий не попадает.

## Команды

| Команда | Что делает |
|---|---|
| `bibvpn init` | Создать пустой `state/bibvpn.yml` |
| `bibvpn check-target HOST` | Проверить сайт как кандидата в SNI: TLS 1.3, HTTP/2, сертификат, «не слишком ли известный» |
| `bibvpn node add NAME IP --sni HOST` | Зарегистрировать сервер и сгенерировать его ключи Reality |
| `bibvpn node list` | Список серверов |
| `bibvpn node set NAME --sni HOST` | Сменить сайт маскировки |
| `bibvpn node set NAME --rotate-keys` | Новые ключи Reality и сертификат Hysteria2 (старые ссылки перестают работать) |
| `bibvpn node set NAME --hy2` / `--no-hy2` | Включить или выключить Hysteria2 (UDP 443) на сервере; `node add ... --no-hy2` создаёт сервер без него |
| `bibvpn node set NAME --disable` / `--enable` | Отключить или вернуть сервер. **После `deploy` на отключённом сервере Xray останавливается, конфиг с ключами удаляется, порт закрывается** |
| `bibvpn node rm NAME` | Забыть сервер. Работает только для отключённого (и уже задеплоенного) сервера; `--force`, если сервера больше нет |
| `bibvpn user add NAME [--note ...]` | Добавить пользователя |
| `bibvpn user list` | Список пользователей |
| `bibvpn user disable` / `enable NAME` | Отключить или вернуть пользователя (после `deploy`) |
| `bibvpn user rm NAME` | Удалить пользователя |
| `bibvpn user rotate-sub NAME` | Новая ссылка подписки (если старая утекла) |
| `bibvpn links NAME [--qr]` | Ссылки `vless://` и `hysteria2://` пользователя |
| `bibvpn sub NAME [--qr]` | Ссылка подписки пользователя (нужен хаб) |
| `bibvpn hub set IP [--domain D]` | Настроить хаб |
| `bibvpn hub rm` | Убрать хаб из состояния |
| `bibvpn monitor set ...` | Интервал, порог, Telegram, тестовые URL |
| `bibvpn monitor test` | Отправить тестовое уведомление с хаба |
| `bibvpn status` | Последние результаты проверок с хаба |
| `bibvpn render` | Сгенерировать файлы в `build/` без деплоя |
| `bibvpn deploy [--check] [--limit NAME]` | Применить изменения на серверах; незнакомые опции уходят в `ansible-playbook` |

Любое изменение состояния попадает на серверы только после `bibvpn deploy`.

**Про `deploy --check`.** Показывает, что изменится, ничего не меняя; добавляет
`--diff`, но файлы с секретами (ключи, UUID, токены) из diff исключены. На ещё ни разу
не развёрнутом сервере предпросмотр ограничен базовой подготовкой: остальные шаги
зависят от файлов, которые создаёт первый настоящий запуск. Об этом выводится
сообщение.

## Структура

```
bibvpn/              CLI и генераторы (Python)
  state.py           модель данных, валидация, миграции
  xray.py            конфиг Xray для серверов
  links.py           ссылки vless://, подписки, клиентские конфиги
  hub.py             файлы хаба: тестовый клиент, мониторинг, Caddyfile
  monitor.py         мониторинг (запускается на хабе, только стандартная библиотека)
  render.py          генерация build/ и инвентаря
  target.py          проверка сайта-кандидата для SNI
  cli.py             команды
ansible/             плейбук и роли: common (защита), xray_bin, xray, hub
tests/               юнит-тесты и tests/integration/run.sh
scripts/             install-xray.sh (закреплённый Xray для тестов и CI)
docs/                документация
```

## Разработка и CI

```bash
make dev           # .venv с зависимостями, Ansible, ansible-lint
make xray          # закреплённый Xray в ~/.local/bin (для проверки конфигов в тестах)
make test          # юнит-тесты (с xray в PATH конфиги проверяет и сам Xray)
make lint          # ansible-lint
make integration   # полный сценарий в Docker (нужны docker и xray)
```

CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)) запускается на каждый PR и
push в `main`:
1. **Lint:** ansible-lint, syntax-check плейбука, bandit, разбор shell-скриптов.
2. **Unit:** pytest на Python 3.10 и 3.12 с настоящим Xray. Пропущенные тесты
   считаются ошибкой.
3. **Integration:** `tests/integration/run.sh` поднимает два контейнера Ubuntu 24.04 с
   systemd (сервер и хаб) и проверяет:
   - `deploy --check` на чистых серверах, без секретов в выводе;
   - полный деплой и повторный деплой без изменений;
   - подключение настоящим клиентом по обоим транспортам;
   - маскировку при зондировании;
   - защиту SSH, фаервол, песочницы и недоступность служб сервера через туннель;
   - подписки по HTTPS;
   - сценарий «сервер упал / поднялся» с уведомлениями;
   - отзыв доступа у пользователя и остановку отключённого сервера.

## Ограничения

- Это средство **обхода блокировок, а не анонимности**. Хостинг знает, кто арендовал
  сервер.
- Хаб в России хранит ссылки всех пользователей. Компромисс описан в
  [SECURITY.md](docs/SECURITY.md).
- Белые списки мобильного интернета пока не обходятся: нужен каскад через хаб (в
  планах).
- Перед коммерческим использованием нужна консультация юриста: в РФ ограничены
  предоставление и реклама средств обхода блокировок.
